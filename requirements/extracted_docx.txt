AUREX
Full-Stack Engineering Internship
Month 3 — Industry-Level Full-Stack Projects & Industry Readiness
1. Month 3 Overview
Duration: 4 Weeks
Expected Workload: 10 Hours per Week
Weekly Submission: Every Saturday
Next Week's Work & Resources: Sent every Sunday Night
Learning Model: Self-Learning + Practical Development + Mentor Review
Mode: Fully Online
Month 3 Objective
The purpose of Month 3 is to move interns from individual technical tasks to complete, industry-style full-stack application development.
By the end of Month 3, interns should be able to:
Analyze a real-world project requirement.
Break a project into frontend, backend, database, and API components.
Design a basic system architecture.
Build reusable React.js components.
Manage application state effectively.
Consume and integrate REST APIs.
Build backend APIs using Node.js and Express.js.
Design and manage MongoDB databases using Mongoose.
Implement authentication and authorization.
Use JWT and bcrypt appropriately.
Perform CRUD operations.
Handle API errors and validation.
Connect frontend, backend, and database.
Use Git/GitHub professionally in a project environment.
Test major application functionality.
Deploy a complete full-stack application.
Write proper project documentation.
Explain their technical implementation independently.
Work on a project without continuous step-by-step mentor guidance.
Month 3 Philosophy
Month 1 focused on:
Frontend Foundation
↓  Month 2 focused on:
React + APIs + Backend + Database
↓  Month 3 focuses on:
Complete Full-Stack Applications + Industry Readiness
The goal is no longer to teach individual technologies separately. Interns should now combine previously learned technologies to solve real-world problems.

WEEK 1 — Project Planning, Architecture & Development Setup
Theme
Real-World Requirement Analysis + System Design + Project Setup
Week 1 Objective
Interns will learn how to approach a complete full-stack project before writing large amounts of code.
The focus will be on:
Requirement → Architecture → Database → API → Frontend → Development Plan
A. Project Selection
Each intern/team will be assigned or approved a real-world project.
Possible project categories:
E-commerce application
Appointment/booking system
Task/project management system
Learning management system
Event management system
Inventory management system
Service marketplace
Expense management system
Job/internship portal
Small business management system
Projects should have enough complexity to demonstrate full-stack skills.
Important: The project must not simply be a basic CRUD form. It should include multiple entities, authentication, API integration, database operations and meaningful business logic.
B. Requirement Analysis
Interns should identify:
Problem statement
Target users
User roles
Core features
Functional requirements
Non-functional requirements
Main user flows
Required data
Authentication requirements
Admin functionality where applicable
Example User Roles
User
Admin
Manager
Service Provider
The exact roles depend on the selected project.
C. System Architecture
Interns should create a basic architecture showing:
React Frontend → REST APIs → Node.js + Express.js → Mongoose → MongoDB
They should understand how data moves through the application.
D. Database Design
Interns should identify:
Collections
Fields
Relationships
Required/optional fields
Data types
Basic indexes where appropriate
Example: Users, Products, Orders, Categories, Payments — depending on the project.
Interns should create a basic ER-style/database relationship diagram where applicable.
E. API Planning
Before implementation, interns should prepare an API list. Example:
POST   /api/auth/register
POST   /api/auth/login
GET    /api/products
GET    /api/products/:id
POST   /api/products
PUT    /api/products/:id
DELETE /api/products/:id
The actual endpoints depend on the project.
F. Project Repository
The project must use GitHub from the beginning.
Recommended structure:

frontend/
backend/
README.md
.gitignore
Interns should use meaningful commits throughout development.

WEEK 2 — Full-Stack Core Development
Theme
Frontend + Backend + Database Integration
Week 2 Objective
Interns will begin implementing the actual project and establish communication between:
React → API → Express → MongoDB
A. Backend Implementation
Interns should implement the project backend using: Node.js, Express.js, MongoDB, Mongoose.
They should create:
Express server
Environment configuration
Database connection
Routes
Controllers
Models
Middleware
Error handling
B. MongoDB/Mongoose
Interns should implement the previously designed database. They should demonstrate:
Schema creation
Models
CRUD operations
Basic validation
Relationships/references where required
Proper database queries
C. REST API Development
Interns should implement the project's major APIs. Expected operations: GET, POST, PUT/PATCH, DELETE.
Where applicable, APIs should include:
Request validation
Appropriate status codes
Error responses
Proper response structure
D. React Frontend
Interns should build the main application interface, using React.js, Components, Props, State, Forms, React Router where required, and API integration.
The frontend should be component-based rather than one large component.
E. API Integration
The React application must communicate with the backend. Interns should implement:
GET requests
POST requests
Update requests
Delete requests
Loading states
Error handling
Success feedback
F. Week 2 Development Milestone
By the end of Week 2, the project should have:
Working React frontend
Working Express backend
MongoDB connection
Major database models
Core REST APIs
Frontend/API communication
At least one complete end-to-end feature
Example flow:
User enters data → React Form → API Request → Express Route → Controller → Mongoose → MongoDB → Response → React UI

WEEK 3 — Authentication, Advanced Features & Testing
Theme
Authentication + Authorization + Business Logic + Testing
Week 3 Objective
Interns will transform the basic application into a more realistic production-style system.
A. Authentication
Interns should implement authentication using: JWT, bcrypt, Protected routes, Login, Registration, Logout/session handling as appropriate.
Required Features (depending on the project)
User registration
User login
Password hashing
Token generation
Token verification
Protected API routes
Protected frontend routes
B. Authorization
If the project has multiple roles, implement role-based access.
Example: User → can access user features. Admin → can access admin dashboard.
Interns should understand the difference between:
Authentication = Who are you?  |  Authorization = What are you allowed to do?
C. Frontend Authentication
React should handle:
Login form

Authentication state
Protected routes
User information

7. Industry-Level Development Practices
During Month 3, interns should start following professional development practices.
Git/GitHub
Commit regularly
Write meaningful commit messages
Avoid uploading broken/unrelated code
Maintain a clean repository
Use branches where appropriate
Keep README updated
Code Quality
Use reusable components
Avoid unnecessary duplication
Use meaningful names
Organize files properly
Handle errors properly
Remove debug code before final submission
Security
Interns must understand basic security practices:
Passwords must be hashed
JWT secrets must not be exposed
.env must not be committed
Database credentials must remain private
APIs should validate incoming data
Protected routes must verify authentication
8. Mentor Responsibilities During Month 3
Mentors are responsible for project supervision, review and technical guidance, not completing the project for interns.
Mentors should:
Review project proposals
Approve project scope
Review architecture
Review weekly milestones
Check GitHub activity
Review code
Identify technical issues
Provide constructive feedback
Help with genuine blockers
Track progress
Conduct final project review
Mentors should NOT:
Write the complete project
Provide complete solutions for normal problems
Continuously guide every coding step
Debug every issue themselves
Allow interns to submit work they cannot explain
The goal is to simulate a professional development environment.

Downloading a complete project and submitting it
Copying a complete GitHub project

Using AI to generate an entire application without understanding it
Learning from tutorials, documentation and examples is allowed.
